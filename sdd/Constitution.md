Constitution - 餐饮 Agent



项目原则



1. 分层清晰：API、Agent、Service、Repository 职责分离。

2. 业务复用：相同业务能力必须由 Service 统一实现，API 和 Agent 不重复实现。

3. 数据安全：关键业务约束必须由确定性代码或数据库保证，不能依赖 LLM。

4. 模块高内聚：模块内部负责自身职责，对外只暴露必要接口。

5. 小步迭代：优先进行小范围、可验证的修改，避免无关重构。

6. 测试保障：新增或修改的业务能力必须配套测试。

7. 最小依赖：没有明确必要性，不引入新的重型依赖。



禁止项



- 禁止 API、Agent、Agent Tool 直接访问 Repository 或数据库。

- 禁止在 API、Agent 中重复实现业务逻辑。

- 禁止 Agent Tool 直接操作数据库。

- 禁止关键业务规则依赖 LLM 判断。

- 禁止为了当前需求进行无关重构。
